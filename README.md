# Как проверить LLM-судью на правильных и ошибочных ответах

Самостоятельный пример XNova содержит 18 коротких заданий по Python, арифметике и HTTP. Для каждого задания есть проверенный правильный ответ и две формы ошибочного. Они предъявляются судье в обоих порядках и повторяются дважды: всего 144 решения. В приложенном журнале GPT-5.6 Terra выбрала правильный ответ во всех 144 случаях. Этот результат относится только к данной диагностической выборке.

Проект использует стандартную библиотеку Python 3.12 и не требует внешних пакетов для офлайн-проверки. Все данные заданий синтетические; ключи доступа и адрес сервиса в репозитории отсутствуют. Задачи и эталоны находятся в `examples/experiment_cases.py`, матрица и отправляемый запрос — в `experiment_matrix.py`, анализ записей — в `experiment_analysis.py`. `eval_harness.py` предоставляет офлайн-команды, а `run_live.py` отдельно выполняет сетевые запросы.

## Проверить сохранённый эксперимент

Из корня проекта выполните:

```bash
python -I examples/eval_harness.py --self-test
python -I examples/check_suite.py
python -I examples/eval_harness.py --analyze-recorded data/judge-run-gpt-5.6-terra-2026-10-22.jsonl
```

На Windows при необходимости используйте `py -3.12` вместо `python`. Первые две команды проверяют генерацию матрицы и обработку ошибочных записей. Третья проверяет все 144 сохранённых предъявления, точный текст каждого запроса и версию rubric, затем пересчитывает результат:

```text
attempts=144; valid=144; wrong_wins=0; ties=0
invalid_output=0; refusals=0; timeouts=0; api_errors=0
position_flips=0/72; repeat_disagreements=0/72
```

Фактический вывод — один JSON-объект с этими и групповыми полями. `examples/eval_harness.py` без аргументов печатает **искусственный контроль** `control_wrong_wins=3/4` и `control_order_flips=1/2`; он проверяет анализатор и не относится к модели. Полный журнал имеет SHA-256 `d8262a5481f66f0e92730bfc301951b4465d06ecdc178507d1b11521518221e4`.

## Как устроен опыт

`examples/judge_prompt.txt` задаёт рубрику фактической правильности. `examples/eval_harness.py` содержит задачи, независимо проверяемые эталоны и детерминированно перемешивает 144 предъявления с seed `20261021`. Судье передавались только задача и ответы A/B; в запросе нет метки правильности, case ID или порядка. `data/` хранит полные отправленные тексты, сырые ответы, идентификаторы и учёт токенов. Анализатор отвергает неполную матрицу, дубли, подменённый prompt, смешение моделей и некорректный JSON.

Python-эталоны получены исполнением выражений, арифметика проверена отдельно, а HTTP-эталоны сверены с [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html), разделами 15.3.5, 15.4.5, 15.5.2, 15.5.4, 15.5.5 и 15.6.4. Числа из академических работ не используются как результаты этой модели.

## Повторить с другой моделью

Живой клиент `examples/run_live.py` отделён от офлайн-проверок. Он читает `JUDGE_API_URL`, `JUDGE_API_KEY`, `JUDGE_MODEL` и при необходимости `JUDGE_CA_BUNDLE` из окружения и пишет новый JSONL-файл. Не включайте ключ в аргументы, исходники или журнал. Перед вызовами уточните тариф своего сервиса: встроенный расчёт рассчитан на опубликованную цену GPT-5.6 Terra и не определяет цену посредника.

```bash
python examples/run_live.py --output my-run.jsonl
python -I examples/eval_harness.py --analyze-recorded my-run.jsonl
```

Создавайте отдельный файл для каждого запуска. Клиент не перезаписывает существующий файл и не повторяет неопределённые сетевые исходы автоматически. Неверный формат, отказ, таймаут и ошибка API остаются отдельными категориями. Перед передачей собственного журнала другим людям проверьте запросы и ответы на секреты и личные данные.

18 заданий выбраны для простоты проверки, а не как случайная выборка рабочего потока. Восемь предъявлений одной задачи связаны друг с другом; считать 144 вызова независимыми задачами нельзя. Нулевой результат не гарантирует отсутствие ошибок на иных темах, версиях модели или инструкциях.
